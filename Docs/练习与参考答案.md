# 机房扩展练习与参考答案

风扇主讲练习与答案见《Unity风扇与巡检培训手册》第 12 章；本文为机房扩展。

先在机房场景操作，每章开始前备份场景。参考答案用于讲评，学员先尝试完成。示例片段应插入说明中的现有类，不要直接当作单独脚本使用。

## 1. 基础操作：备用设备

**题目**：新增备用控制柜，放在现有设备后方；命名、ID、材质均与原设备区分，保存后重开。

**参考步骤**：

1. 把 `Prefabs/control-01.prefab` 拖入 Devices；设位置 `(5.1, 0, 4)`，对象名为 `control-02`。
2. 在 DeviceController 中将 deviceId 改为 `control-02`，displayName 改为“备用控制柜”。
3. 复制 BlueSteel 材质为 BackupSteel，调为深紫色，仅赋给新实例 Housing。
4. Ctrl+S 保存，离开再打开场景；配置检查不应报告重复 ID。

**扩展说明**：该练习只验证 Prefab 和序列化；新增设备不会自动出现在目录、巡检路线和 HTTP 服务中。综合练习再显式注册。

## 2. 动画：改变柜门角度与风机速度

**题目**：让柜门最大打开 80 度，开关过渡 0.6 秒；风机循环耗时两秒。

**参考步骤**：

1. 先复制 Device.controller 及要改的 Clip，赋给测试设备，保留其他设备作为对照。
2. 将副本 DoorOpen 动画 `DoorPivot/localEulerAnglesRaw.y` 的两个恒值关键帧改为 `-80`。
3. 在 Door 层把两条过渡 Duration 都改为 `0.6`，保持 Has Exit Time 关闭。
4. Rotor 层 Active 状态 Speed 改为 `0.5`，一秒长的动画因此两秒播放一次。
5. 运行后同时开启柜门、转子和告警，确认三层仍同时工作。

**解释**：门的实际转轴是 DoorPivot。Clip 记录的是属性目标，过渡负责从当前状态混合到新状态；直接移动门中心会失去正确铰链。

## 3. C#：运行状态摘要

**题目**：在 DeviceController 增加一个返回中文状态的方法，给 Inspector 或 Console 调试使用。

**参考答案**：

```csharp
public string DescribeStatus()
{
    if (alarm) return displayName + "：告警，请检查";
    return displayName + (running ? "：运行正常" : "：已停止");
}
```

**验收**：停止返回“已停止”，启动返回“运行正常”，无论是否运行，只要 alarm 为 true 就优先返回告警。

**巡检问答**：为什么 Next 不能在 Moving 时递增？因为当前点尚未到达，任意递增会跳过检查。为什么暂停前保存旧状态？因为暂停可能发生在移动中，也可能发生在等待检查时，继续应恢复到暂停前的位置和状态。

**速度练习**：把 PatrolController.speed 改为 1.5，观察耗时变化；运动仍乘 Time.deltaTime，因此不同帧率下速度定义一致。

## 4. HTTP：直接调用与异常处理

**题目**：不通过 Unity，直接查询设备并启动风机，然后发送一个未知设备请求。

```powershell
Invoke-RestMethod http://127.0.0.1:8080/api/devices
Invoke-RestMethod http://127.0.0.1:8080/api/devices/fan-01/commands `
  -Method Post -ContentType 'application/json' -Body '{"command":"start"}'
Invoke-RestMethod http://127.0.0.1:8080/api/devices/missing/commands `
  -Method Post -ContentType 'application/json' -Body '{"command":"start"}'
```

**预期**：前两次返回 200，最后一次返回 404；Unity HTTP 模式点同步后风机会启动。

**错误 JSON**：发送 `{broken` 作为请求体，服务返回 400，而不是退出。执行 `python -m unittest discover -s Server -v` 可重复验证。

**断网练习答案**：停止服务→检查并提交→界面显示失败且列表保留→重启服务→再次提交→成功后检查文件。失败不会调用 Clear；成功必须同时满足响应 ok、batchId 和 count 匹配。

**去重问答**：在网络延迟时，服务端可能已写入但客户端没收到响应。相同 batchId 重试不会重复写入；记录发生修改后批次 ID 改变，代表一次新的提交。

## 5. Editor：规则、撤销与完整扩展

**题目 A**：增加“设备显示名称不能为空”的检查。

在 TrainingValidator.Scan 的设备循环中添加：

```csharp
if (string.IsNullOrWhiteSpace(device.displayName))
    result.Add(new Issue { message = "设备显示名称不能为空", target = device });
```

把某台设备显示名清空，检查后可定位；恢复名称后通过。

**题目 B**：新增第五个巡检点并验证 Undo。

打开路线编辑器→查找当前场景路线→Scene 视图移动到目标观察位置→新增巡检点→选择该点并绑定设备→拖动位置手柄→Ctrl+Z→保存→重开场景。新增点位置与顺序由数组决定，Gizmos 和 Handles 只是编辑器辅助显示。

**题目 C：第五台设备全链路接入**

1. 按第 1 章创建 `control-02`。
2. 将其加入 Training Systems/TrainingDashboard.devices 数组；增加 UI 设备按钮，复制 DashboardAction，设 action=`select`、deviceIndex=`4`，并修正目录标题数量。
3. 新增并绑定巡检点，将点放进 PatrolController.points 数组。
4. 在 Server/server.py 的初始设备列表增加 `('control-02', '备用控制柜')`；重启服务。
5. 更新后端测试的数量断言，增加新设备查询/命令的断言。
6. 本地与 HTTP 分别检查新增设备，提交记录，配置检查应通过。

**讲评重点**：这是教学用显式引用，不依赖隐式全局查找。学员能看清配置如何连接对象。设备 ID 不是显示名称，改中文名无需改 API；改 ID 必须同步场景、后端与记录关联。
