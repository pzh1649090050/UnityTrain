# 机房扩展教学补充

对象：有基本编程概念、尚未使用 Unity 的学员。建议每日 6 小时：概念与演示 2 小时、跟做 2 小时、独立练习及讲评 2 小时。每天先复制工程或创建本地版本记录，避免覆盖前一天成果。

## 课前准备

统一 Unity 2022.3.55f1c1、Windows（工程已附中文字体）。培训机第一次导入时需能访问 Unity 包源；讲师提前导入并打开两个场景。HTTP 章节准备 Python 3.10+；服务无需 pip 安装。学员机器若无 IDE，可通过 Unity Preferences → External Tools 指定 Visual Studio 或其他 C# 编辑器。

先体验入口→机房→启停风机→打开机柜门→告警→自动巡检→记录→提交。先用本地模式，明确服务尚未启动时不应显示“提交成功”。

## 第一天：基础操作与机房搭建

**学习目标**：理解 Scene 与 Game、Hierarchy、Inspector、Project、Console；掌握 GameObject、Transform、组件与 Prefab。

**演示步骤**：

1. 打开入口场景，比较编辑态与 Play 模式，强调播放期间的对象修改通常不保存。
2. 在机房 Scene 视图使用右键、WASD、鼠标滚轮及 F 聚焦，演示 W/E/R 工具和 Local/Global。
3. 展开 Environment、Devices、Inspection Route 和 Training Systems，区分父子层级及世界/局部坐标。
4. 选中柜门 DoorPivot，再选 Door，观察转轴与网格的偏移；说明为何不能把门本体中心当铰链。
5. 找到设备 Prefab，演示实例覆盖、还原覆盖、拖入新实例及修改材质。
6. 检查 Collider、Camera、Light 和 Canvas，理解组件通过引用协作。

**练习**：添加备用控制柜，修改显示名和唯一 ID；建立新材质，调整基座位置并保存场景。见练习答案第 1 章。

**验收**：重开场景仍存在设备；实例与原 Prefab 的区别可解释；Console 无错误。

**常见问题**：粉色材质通常是 Shader/管线不匹配；物体不可见先检查位置、缩放与摄像机；运行时移动不等于已保存场景。

## 第二天：动画与 Animator 状态

**学习目标**：区分 Animation Clip 与 Animator Controller，理解参数、状态、过渡、循环及多层动画。

**演示步骤**：

1. 打开 `Animations/Device.controller`，观察 Door、Rotor、Alarm 三层及默认权重。
2. 播放机房，选中设备，在 Animator 窗口观察 DoorOpen、Running、Alarm 参数。
3. 使用 UI 和 Inspector 调试按钮切换状态，跟踪 Idle/Active 及过渡时间。
4. 在 Animation 窗口检查 DoorPivot 欧拉角曲线；强调动画路径相对于 Animator 所在对象。
5. 检查 RotorSpin 的线性 0→360 曲线及 Loop Time，解释为何旋转需要连续循环。
6. 检查告警灯缩放曲线；颜色由脚本的 MaterialPropertyBlock 更新，动画负责脉冲。

**练习**：调整开门角度、过渡时间及转速，制作一个不破坏原资源的慢速动画副本。

**验收**：门围绕铰链旋转，风机启停可切换，告警清除后恢复正常，三层互不抢占属性。

**常见问题**：路径改名导致动画失效；参数大小写不一致不触发；层权重为零时不生效；Inspector 直接改 bool 并不等同于调用刷新逻辑。

## 第三天：C# 设备交互与巡检

**学习目标**：掌握字段、方法、引用、条件、集合、MonoBehaviour 生命周期、Raycast、事件和简单状态机。

**演示步骤**：

1. 从 DeviceController 的序列化字段、Start、ApplyCommand、ApplyState 读起。
2. 在 DevicePicker 设置断点，观察 ScreenPointToRay、RaycastHit、GetComponentInParent。
3. 说明 EventSystem.IsPointerOverGameObject 如何阻止点 UI 时误选场景。
4. 阅读 FlyCamera 的 Time.deltaTime、局部方向和输入框焦点处理。
5. 阅读 InspectionProgress，画出 Manual→Moving→AtPoint→Moving→Completed，以及暂停/恢复分支。
6. 阅读 PatrolController.Update 的 MoveTowards 和 Slerp，演示自动与手动控制切换。
7. 完成四个巡检点，演示同设备复检覆盖、本轮结果列表和重置。

**练习**：新增运行状态摘要方法；调整巡检速度；解释为何下一点必须在到点后执行。

**验收**：暂停不移动、继续从原位置移动、切手动不受自动脚本干扰；输入备注时 WASD 不移动摄像机。

**常见问题**：空引用先检查 Inspector；物体须有 Collider 才能射线命中；不要用每帧固定距离代替每秒速度；不要让两个脚本同时写摄像机 Transform。

## 第四天：HTTP、JSON 与检查结果提交

**学习目标**：掌握请求与响应、GET/POST、UTF-8 JSON、协程、超时、错误处理和前后端状态边界。

**演示步骤**：

1. 启动 Server/启动服务.cmd，用浏览器查看 `/api/devices`。
2. 阅读接口文档与 TrainingApi，解释 using 释放请求、UploadHandlerRaw、DownloadHandlerBuffer 和 yield return。
3. 在机房切换 HTTP 模式，同步四台设备，执行风机启动和告警，观察服务日志。
4. 阅读 DeviceData/DeviceList，解释 JsonUtility 为什么需要对象包装数组。
5. 完成检查并提交，打开 inspections.jsonl 检查 batchId、UTC 时间与中文备注。
6. 停止服务再提交，观察失败且记录保留；重启服务后重试，确认没有假成功。
7. 使用 Network 配置修改超时；讲解 HTTP 状态错误与 JSON 语义错误的区别。

**练习**：用 PowerShell 调用设备接口，模拟未知设备和错误 JSON；解释本地模式数据为何不会自动上传。

**验收**：真实请求能更新场景；错误地址有提示；无服务时能切回本地演示；提交失败不丢当前记录。

**常见问题**：端口占用改端口并同步修改客户端；127.0.0.1 指当前机器；服务输出是日志而非报错窗口；不要把协程当作可随意阻塞的后台线程。

## 第五天：Editor 脚本与综合练习

**学习目标**：区分运行时与 UnityEditor API；掌握 CustomEditor、SerializedObject、EditorWindow、Scene Handles、Undo 与场景保存。

**演示步骤**：

1. 比较 Training.Runtime 与 Training.Editor asmdef，解释编辑器代码为何不能进入 Player。
2. 阅读 DeviceInspector，观察默认字段、提示与播放态按钮。
3. 打开巡检路线编辑器，查找路线，从 Scene 视角添加点并绑定设备，调整数组顺序。
4. 在 Scene 视图拖动手柄，Ctrl+Z 撤销；保存并重开场景验证。
5. 人为设置重复 ID、空设备引用和空路线，运行配置检查并定位、修复。
6. 阅读 TrainingProjectBuilder，说明资源生成器是讲师工具，不是运行时依赖。
7. 执行 Test Runner，阅读一条巡检状态测试，再通过培训菜单构建 Windows 程序。

**综合练习**：添加第五台设备、巡检点和配置检查规则，并解释完整数据流。界面目录、dashboard.devices、路线与后端设备表都需更新；这是扩展练习，不是拖入 Prefab 就自动注册。

**验收**：修改可撤销、可保存，检查可定位，Windows 构建无 UnityEditor 引用错误。

**常见问题**：只修改字段但未标记脏导致不保存；使用普通赋值不自动支持 Undo；生成器会覆盖生成资源，课堂修改须先备份。

## 三天压缩安排

| 天 | 内容 | 必做练习 |
|---|---|---|
| 1 | 第一天基础 + 第二天动画 | 修改 Prefab、柜门角度、Animator 参数 |
| 2 | 第三天 C# + 巡检 | 追踪点击流程，完成暂停/恢复和四点记录 |
| 3 | 第四天 HTTP + 第五天 Editor | 成功提交与断网重试，新增巡检点、撤销与配置检查 |

三天方案把复杂资源生成代码留作课后阅读，不删减 HTTP 与 Editor 的实操。
