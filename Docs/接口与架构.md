# 主讲与扩展案例架构

## 风扇主讲案例

03_FanTraining 的 FanTrainingController 负责两个 uGUI 按钮。ToggleFan 设置 Fan.controller 的 Running Bool，Rotor 的 Clip 负责旋转；ToggleInspection 切换 Play/Pause/Resume，结束事件复位探针和检查灯。巡检未配置完时按钮禁用，便于先完成动画与 UI 章节。

Main Camera 由 Cinemachine Brain 驱动；FanInspection.playable 通过三段 Cinemachine Shot 编排镜头，Animation Track 驱动探针，Activation Track 控制灯，Signal Track 调用检查节点方法。Timeline 不直接控制扇叶，避免与其 Animator 争抢属性。

FanTrainingInspector 和 FanTrainingTools 是 Editor-only 教学示例：检查引用、定位转轴、Undo 修改 Running 状态速度与保存资源。完整操作教程见《Unity风扇与巡检培训手册》。

## 机房扩展接口与架构

## 代码阅读顺序

1. **DeviceController**：单台设备的数据与视觉状态，演示字段、方法及 Animator 参数。
2. **DevicePicker / FlyCamera**：Input Manager、屏幕射线与摄像机控制。
3. **TrainingModels**：可序列化数据、设备 ID 校验、纯 C# 巡检状态机与记录集合。
4. **PatrolController / InspectionPoint**：把状态机连接到场景点位及摄像机；到点使用事件通知 UI。
5. **TrainingDashboard / DashboardAction**：交互编排、模式切换、记录、HTTP 回调及 UI 展示。按钮持久化绑定 DashboardAction.Execute，Inspector 中可追踪。
6. **TrainingApi / TrainingSettings**：可配置的 HTTP 协程传输，业务解析留在调用处。
7. **Editor 下的三个工具**：Inspector、路线编辑及配置检查。TrainingProjectBuilder 用于生成并保存场景资源。

运行时代码只引用 UnityEngine/uGUI；Editor 独立程序集引用 UnityEditor；测试程序集独立于 Player。

## 数据流

本地模式：按钮/射线 → Dashboard → DeviceController.ApplyCommand → Animator 参数与灯材质。

HTTP 模式：按钮 → TrainingApi.Send → Python 服务 → DeviceData JSON → ApplyState → 场景。请求失败不提前改场景；同步以设备 ID 匹配，不靠数组顺序。

巡检：路线 Moving → 到点 AtPoint → 选择对应设备 → Record → 下一点；暂停保存前一状态，手动模式停止自动 Transform 更新。完成最后一点后进入 Completed，可手动漫游。

记录：deviceId 为本轮去重键，复检覆盖旧结果；Record 生成新 batchId，Submit 快照复制记录，等待响应时阻止编辑记录及重置。服务端按 batchId 防止重试重复写入。

## HTTP 协议

基础地址 `http://127.0.0.1:8080`，UTF-8 JSON。服务只绑定回环地址。正常返回 200；未知接口或设备 404；请求格式/字段/命令错误 400；保存文件失败 500。

### GET /api/devices

```json
{"devices":[{"id":"fan-01","name":"通风风机","running":false,"doorOpen":false,"alarm":false}]}
```

实际返回四台：cabinet-01、fan-01、pump-01、control-01。服务启动时状态全部为 false。Unity 要求 devices 数组存在、ID 非空且不重复；未知场景设备不会被自动创建，同步提示匹配数量。

### POST /api/devices/{id}/commands

请求：

```json
{"command":"start"}
```

指令：`start`、`stop`、`open`、`close`、`alarm`、`clearAlarm`。动作均为显式设值，可安全重复执行。

响应：

```json
{"device":{"id":"fan-01","name":"通风风机","running":true,"doorOpen":false,"alarm":false}}
```

四种教学设备共用同一套命令，以便学员比较动画、状态与数据流；开门和转子是不同 Animator 层。

### POST /api/inspections

```json
{
  "batchId":"5f3f5c361b7e43c99b93129def203f2b",
  "records":[{
    "deviceId":"fan-01",
    "result":"abnormal",
    "note":"检查到振动",
    "checkedAt":"2026-11-19T04:00:00Z"
  }]
}
```

`batchId` 为非空字符串，`records` 非空；deviceId 必须已知，result 为 normal 或 abnormal，note 为字符串。checkedAt 由 Unity 生成 UTC ISO 8601 字符串。

成功响应：

```json
{"ok":true,"batchId":"5f3f5c361b7e43c99b93129def203f2b","count":1}
```

记录追加至 `Server/data/inspections.jsonl`，每行一个批次，额外包含 receivedAt。服务重启后读取已有 batchId。设备状态不持久化。教学服务使用线程锁防止同时修改状态或交错写文件，请求体限制 64 KiB。

错误响应示例：`{"error":"设备不存在"}`。Unity 展示 HTTP 状态、网络错误及服务返回内容。

## 资源和平台边界

- 输入使用 Unity 传统 Input Manager，沿用模板的 Horizontal、Vertical、Mouse X/Y。
- UI 使用 Canvas/uGUI，参考尺寸 1600×900。建议 16:9 窗口教学；小窗口可调整至推荐尺寸。
- 中文字体使用随包的 Noto Sans CJK SC OTF；Canvas 与场景文字显式引用，避免动态字体序列化缺失纹理。
- Animator 有 Door、Rotor、Alarm 三层，各动画只绑定自己的 Transform 属性；灯颜色通过 MaterialPropertyBlock，不修改共享材质资产。
- 本地模式并非 HTTP 降级假成功。切模式只切后续操作路径，不自动同步、不上传已有本地设备状态。
- Windows 为 Development/Mono 构建，允许教学明文 HTTP；非开发构建需要重新评估 HTTP 配置与服务部署。
